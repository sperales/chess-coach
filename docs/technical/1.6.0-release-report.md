# Chess Coach 1.6.0 - Release candidate report

## Scope delivered

Version 1.6.0 introduces the Training Quality & Coach Foundation without replacing the legacy selector by default. The implemented circuit is:

```text
current stored analysis
→ canonical Training Opportunity
→ hard filters + Pedagogical Score
→ Mastery + Recent Performance
→ one Coach Decision
→ shadow Selection v2 + quality-first Composer
→ existing Flash / Scenario delivery
→ factual result + observed difficulty + deferred review
```

The product audit and approved decisions are retained at repository root. The previous roadmap is archived in `docs/roadmap/archive/ROADMAP_PRE_V1.6.md`; `ROADMAP.md` is the current outcome-oriented roadmap.

## Architecture and data

- Migration: `sql/migrations/037_changes_1.6.0.sql`.
- Fresh-install parity: `sql/install.sql`.
- Taxonomy: ten stable Spanish concepts with versioned signal mappings.
- Canonical domain: opportunities, concepts, multiple sources and append-only audits.
- Quality: stable hard-rejection reasons, component scores, thresholds and algorithm versions.
- Selection: persisted legacy/v2 comparison, structured reasons and rollout modes.
- Learning: concept Mastery, Recent Performance, observed difficulty, mastery events and due review.
- Coach: one persisted current decision with evidence, confidence and reassessment conditions.
- Delivery: opportunity and selection provenance retained on existing session items.
- Timing: first legal submitted move stored separately for Flash and Scenario.

## Backfill and rollout

The Profile batch action reuses stored completed analyses. It is bounded by batch size and analysis count, idempotently links equivalent sources and leaves failed items pending for a later retry. No historical attempts are rewritten and no mass Stockfish analysis is started.

The release configuration is `shadow`. Legacy still controls visible Training; Selection v2 stores what it would have selected. `active` exists for an explicit controlled validation only. `legacy` is the non-destructive rollback.

## Experience delivered

- Home, Training, Nova and generated focus goals consume one Coach Decision.
- Player DNA remains longitudinal evidence and no longer presents a competing current recommendation.
- Review exposes training only through a current, published and delivered canonical opportunity.
- Finalized Flash and Scenario activity share streak and daily/weekly progress semantics.
- The training closure reports concept, autonomy, Mastery evidence, next review and factual Nova copy.
- Nova supports semantic `idle`, `thinking`, `correct`, `error`, `hint`, `explaining` and `session_complete` states, with restrained CSS reactions and reduced-motion support.

## Must Have status

Implemented: taxonomy, canonical opportunities, currency, deduplication, filters, scoring, shadow selection, difficulty, format routing, Mastery, Recent Performance, deferred review, Coach Decision, Composer, selection reasons, factual closure, streak/goals, structured Nova memory inputs, bounded backfill and minimum observability.

## Very Nice to Have status

Implemented: reactive Nova states using the existing local sprite, CSS and vanilla JavaScript, including delayed thinking on real requests and `prefers-reduced-motion`.

## Should Have status

- Implemented: bounded Profile diagnostics and limited deterministic within-training adaptation.
- Deferred: a dedicated internal opportunity-audit screen. Audit data and bounded summaries exist, but no additional operational page was added.
- Deferred: stronger value comparison messaging until production evidence is sufficient.

## Risks and debt

- Score weights, publication thresholds and priority weights are v1 hypotheses; production shadow evidence must be reviewed before activation.
- Deterministic canonical similarity catches exact pedagogical identity, not semantic near-duplicates.
- Sparse evidence limits Mastery confidence and Coach Decision precision.
- Backfill batches are restartable through pending/idempotent state; each HTTP call creates a separate operational run record rather than resuming one long transaction.
- Transfer to later real games is deliberately not inferred in this release.

## Roadmap decisions

Kept: advanced openings/repertoire, richer repetition, calibrated difficulty, Nova evolution and automation where they remain compatible with the product direction.

Reordered: Transfer & Adaptation now precedes conversational AI, because natural coaching needs reliable evidence of what transfers to real games.

Removed from active roadmap: XP, currency, rankings, leagues, general achievements and hint economy. They remain outside the learning-first product direction rather than being silently postponed.
